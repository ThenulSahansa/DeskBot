# DeskBot

DeskBot is an open-source, AI-powered desktop companion powered by an **ESP32-C3 SuperMini** microcontroller, an **INMP441 digital microphone**, and an **SSD1306 OLED display**. It communicates over **Bluetooth Low Energy (BLE)** with an Android companion application (**DeskDroid**), which bridges real-time bidirectional voice streaming to Google's **Gemini Live Multimodal API**.

---

## Architecture & Data Flow

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │                              DeskBot Device                            │
 │                                                                        │
 │   [INMP441 Mic] ──(I2S 16kHz)──> [ESP32-C3 SuperMini] ──(I2C)──> [OLED]│
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │
                        Bluetooth Low Energy (BLE 5.0)
                        - Audio stream notify (16-bit PCM)
                        - VAD markers (VOICE_START / VOICE_END)
                        - Response text write (DISPLAY_END)
                        - OTA firmware updates
                                     │
 ┌───────────────────────────────────▼────────────────────────────────────┐
 │                           DeskDroid (Android)                          │
 │                                                                        │
 │   - Bridges BLE audio packets to WebSocket frames                      │
 │   - Applies 6x software audio gain and peak amplitude monitoring       │
 │   - Guards against silence / false triggers to prevent hallucinations  │
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │
                   WebSocket (WSS) BidiGenerateContent
                   - Model: models/gemini-3.8-live
                   - In: audio/pcm;rate=16000
                   - Out: outputAudioTranscription (text) & audio PCM
                                     │
 ┌───────────────────────────────────▼────────────────────────────────────┐
 │                     Google Gemini Live Cloud Backend                   │
 └────────────────────────────────────────────────────────────────────────┘
```

## Pin Configurations

### 1. INMP441 I2S Microphone Wiring

| INMP441 Pin | ESP32-C3 SuperMini Pin | Description | Critical Notes |
| :--- | :--- | :--- | :--- |
| **VDD** | **3.3V** | Power Supply | **Do NOT connect to 5V!** 3.3V only. |
| **GND** | **GND** | Ground | Common system ground. |
| **SD** | **GPIO 6** | Serial Data (DOUT) | Audio data line into ESP32 I2S DIN. |
| **SCK** | **GPIO 4** | Serial Clock (BCLK) | Bit clock generated by ESP32. |
| **WS** | **GPIO 5** | Word Select (LRCLK) | Frame clock / Word select. |
| **L/R** | **GND** | Left/Right Channel Select | **MUST BE CONNECTED TO GND!** Setting to GND selects the **Left** channel. If left floating or tied to 3.3V, the microphone transmits on the Right channel while firmware listens on Left, reading all zeroes (silence). |

### 2. SSD1306 OLED Display Wiring (I2C)

| SSD1306 Pin | ESP32-C3 SuperMini Pin | Description |
| :--- | :--- | :--- |
| **VCC** | **3.3V** | Power Supply (supports 3.3V) |
| **GND** | **GND** | Ground |
| **SDA** | **GPIO 2** | I2C Serial Data |
| **SCL** | **GPIO 3** | I2C Serial Clock |

*Default I2C Address:* `0x3C`

## BLE Protocol & GATT Specifications

- **Device Name:** `DeskBot`
- **Negotiated MTU:** Up to 517 bytes (negotiated automatically by DeskDroid)
- **Primary Service UUID:** `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`

| Characteristic | UUID | Properties | Format / Payload | Description |
| :--- | :--- | :--- | :--- | :--- |
| **Command** | `6E400002-...` | `WRITE`, `WRITE_NR` | ASCII string (`OTA_BEGIN:<bytes>`, `OTA_ABORT`, `OTA_END`) | Receives commands (OTA update control, system commands) |
| **Status** | `6E400003-...` | `READ`, `NOTIFY` | UTF-8 String (`VOICE_START`, `VOICE_END`, OTA messages) | Sends status and speech turn events from ESP32 to phone |
| **Firmware Data** | `6E400004-...` | `WRITE` | Binary byte array | Receives chunked firmware binary for Over-The-Air BLE updates |
| **Audio Stream** | `6E400005-...` | `READ`, `NOTIFY` | 16-bit signed PCM (16 kHz, Little-Endian, Mono) | Streams microphone audio in 240-byte chunks (~120 samples each) |
| **Display Text** | `6E400006-...` | `WRITE`, `WRITE_NR` | UTF-8 String chunks ending with `DISPLAY_END` | Receives AI response text to render on the OLED display |

## Core Capabilities

1. **On-Device Voice Activity Detection (VAD):**
   - Samples audio continuously at 16,000 Hz via I2S DMA.
   - Calculates real-time Root-Mean-Square (RMS) amplitude with hardware bit shifting (`>> 14`).
   - Automatically detects speech start (`RMS > 120`), updates display to `"Listening..."`, and begins streaming BLE audio packets.
   - Automatically detects silence (`650 ms` timeout), updates display to `"Thinking..."`, sends `VOICE_END`, and stops BLE transmission.

2. **Bidirectional Multimodal AI Streaming (Gemini Live):**
   - The Android companion buffers BLE audio packets into ~50 ms chunks (1600 bytes) and streams them via WebSocket `realtimeInput.mediaChunks` (`audio/pcm;rate=16000`).
   - Software gain (6x) amplifies subtle speech without clipping.
   - Turn completion commits user speech with `clientContent: { turnComplete: true }`.
   - Real-time text responses are extracted from `serverContent.outputTranscription.text` (and audio transcription) and streamed back to the OLED.

3. **Dynamic OLED Word-Wrapping & Auto-Scroll:**
   - Word wraps long text to 21 characters per line.
   - Automatically scrolls to the newest lines if the text exceeds 8 lines (for 128x64) or 4 lines (for 128x32).

4. **Wireless OTA Firmware Updates Over BLE:**
   - No Wi-Fi or router configuration required on the ESP32.
   - The phone downloads binary assets from GitHub Releases (or local storage) and flashes the ESP32 partition directly over BLE using Arduino's `Update.h`.

## Setup & Flashing Guide

### ESP32-C3 Firmware (`firmware/firmware.ino`)

1. Open Arduino IDE (v2.x recommended).
2. Install the **esp32** board package (Espressif Systems) version `3.0.0` or newer.
3. Install the required libraries via Arduino Library Manager:
   - `Adafruit GFX Library`
   - `Adafruit SSD1306`
4. Board Settings in Arduino IDE:
   - **Board:** `ESP32C3 Dev Module`
   - **Flash Size:** `4MB (32Mb)`
   - **Partition Scheme:** `Minimal SPIFFS (Large APPS with OTA)` or `Default 4MB with ffat`
   - **USB CDC On Boot:** `Enabled`
   - **Upload Speed:** `921600`
5. Connect your ESP32-C3 via USB-C. If it fails to enter bootloader mode automatically, hold down the **BOOT** button, press and release the **RESET** button, then click **Upload**.

### Android Companion App (`DeskDroid`)

1. Open the `DeskDroid` folder in **Android Studio** (Koala / Ladybug or newer).
2. Open `DeskDroid/app/src/main/java/com/example/deskbot/GeminiLiveManager.kt`.
3. Set your valid Gemini API key in `companion object`:
   ```kotlin
   var API_KEY = "YOUR_GEMINI_API_KEY"
   ```
4. Build and install the app on an Android device with Bluetooth and Location permissions granted.

## Bug Fixing & Troubleshooting Reference

Use this guide when diagnosing or resolving issues across the firmware, BLE, or Gemini Live layers:

### 1. Gemini Live WebSocket Closes Immediately (Error `1007: Precondition check failed`)
- **Cause:** Attempting to disable server-side VAD using `"realtimeInputConfig": { "automaticActivityDetection": { "disabled": true } }`, or sending manual `activityStart`/`activityEnd` packets. The `models/gemini-3.8-live` model rejects this payload.
- **Resolution:** Do **not** include `realtimeInputConfig` in `sendSetup()`. Let server-side detection remain enabled by default, and commit speech turns using `clientContent: { turnComplete: true }`.

### 2. Gemini Live WebSocket Closes (Error `1007: The requested combination of response modalities (TEXT) is not supported`)
- **Cause:** `gemini-3.8-live` (audio-native live model) does not allow `responseModalities: ["TEXT"]`.
- **Resolution:** Set `"responseModalities": ["AUDIO"]` in `generationConfig`, and enable `"outputAudioTranscription": {}` in setup to receive the textual transcript of the response.

### 3. Gemini Outputs Repetitive Generic Answers / Hallucinations ("Staying in shape involves...", "Go to settings...")
- **Cause:** The model received an empty/silent turn with `turnComplete: true`. This occurs when:
  1. The microphone `L/R` pin is floating or wired to `3.3V` instead of `GND` (ESP32 reads all zeros).
  2. The firmware's `VAD_RMS_THRESHOLD` was set too high (e.g. `500`), so normal speech was cut off and only a mic tap or silence was sent.
- **Resolution:**
  - Verify INMP441 **L/R** pin is soldered directly to **GND**.
  - Keep `VAD_RMS_THRESHOLD` around `100 - 150` with `>> 14` bit shift in `firmware.ino`.
  - Ensure the silence guard in `GeminiLiveManager.kt` is active: turns with `turnMaxPeak < 35` or fewer than 3 chunks are dropped before prompting Gemini.

### 4. OLED Display Shows Nothing or Displays Garbage
- **Cause:** Incorrect I2C pins or bad display address.
- **Resolution:**
  - Check that `DISPLAY_SDA` is **GPIO 2** and `DISPLAY_SCL` is **GPIO 3**.
  - Verify OLED power is 3.3V and I2C address is `0x3C`.
  - For 128x32 displays, change `#define SCREEN_HEIGHT 64` to `#define SCREEN_HEIGHT 32` in `firmware.ino`.

### 5. BLE Audio Stuttering or High Packet Loss
- **Cause:** Packets sent too quickly without MTU negotiation, overflowing ESP32 BLE TX rings.
- **Resolution:**
  - `firmware.ino` uses `delay(3)` between sub-chunk notifications and limits chunks to `BLE_AUDIO_CHUNK` (240 bytes).
  - DeskDroid requests MTU 517 upon connection. Ensure MTU negotiation succeeds (logged in Terminal Log).

### 6. App Crashes with `ConcurrentModificationException` in TerminalLog
- **Cause:** BLE characteristic callbacks run on background Binder threads while Jetpack Compose reads `SnapshotStateList` on the Main UI thread.
- **Resolution:** Always dispatch log calls to the main thread via `runOnUiThread` or `mainHandler.post { ... }` as implemented in `logUi()` in `GeminiLiveManager.kt` and `MainActivity.kt`.
